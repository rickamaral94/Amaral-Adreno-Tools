Aceito a a800. Conferi os contraexemplos no código, e os dois procedem:
(1) tu_get_image_memory_requirements: uma imagem só com SPARSE_BINDING tem alinhamento os_page_size, então um unbind opaco de 4 KiB dentro de um bind de 128 KiB remove o bloco de 64 KiB vizinho.
(2) tu_CreateBuffer passa pCreateInfo->size para tu_sparse_vma_init. Com o sparse1, num buffer de 4097 bytes o tamanho informado é 65536 e a VMA é de página, então um bind válido falha.
O (2) é regressão possível do sparse1 contra a 5.8.17.1. Avisei o Rick para não testar o sparse1.

sparse2 (docs/research/lab-kgsl-sparse-bind-split-v2.patch, commit no ccr-05e1d523-htngw2), só no KGSL, via tu_sparse_bind_granularity() (65536 no KGSL, os_page_size nos demais):
a) BIND dividido em 64 KiB;
b) alinhamento de 64 KiB para buffer sparse e para imagem com SPARSE_BINDING;
c) VMA de buffer e de imagem arredondada para o mesmo bloco, igual ao tamanho informado;
d) bind de imagem não opaca não atravessa tile;
e) mip tail de residência já é múltiplo do bloco, sem mudança.
Uso a granularidade de 64 KiB para todos os recursos, em vez de split de 4 KiB para imagem opaca, para não multiplicar ranges por 16.
